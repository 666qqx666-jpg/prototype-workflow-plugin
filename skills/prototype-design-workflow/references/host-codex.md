# Codex 原型任务宿主适配

仅当当前宿主支持 Codex fork、派生任务或诊断分支时读取。本参考只负责上下文继承和回传，不改变 Prototype 核心门禁。

如果用户要通过 Codex fork / 派生到本地开诊断子分支，主分支不要为了诊断提前生成大段边界包。因为 fork 会继承主分支全部上下文，正确动作是在 fork 后先让诊断子分支自生成边界卡，完成上下文瘦身和角色重置。

给用户这个低摩擦启动提示：

```markdown
你现在是诊断分支，不是主分支。先不要修改代码，也不要继续推进项目。

请先从继承的主分支上下文中，生成一份“诊断分支边界卡”，用于重置你的工作边界。你需要整理：

- 当前项目是什么
- 当前项目不是什么
- 当前分支职责
- 主分支当前阶段
- 这次要排查的异常
- 材料优先级
- 正确基线
- 禁止误区
- 验收路径
- 继承上下文中是否存在互相冲突的裁决

如果发现主分支继承上下文里有互相冲突的裁决，请先列出冲突，不要选边，不要继续推断。

生成后先停下，等我确认排查重点。
```

诊断结束时，子分支只回传极简行动包，不回传知识库候选或长篇复盘：

```markdown
## 主分支行动包

- 诊断对象：
- 根因一句话：
- 主分支需要修改：
- 主分支需要重新加载的文件：
- 主分支验收检查点：
- fork 内是否改过文件：
- 不需要主分支处理的事项：
```

如果是非 fork 的多 agent 分工，且对方没有继承主分支上下文，才由当前对话生成简版任务卡。任务卡要包含：本项目是 / 不是、禁止归入、P0 必读、页面基线、组件参考、本次只新增、必须保留 / 禁止改、真实验收路径。

如果是新开的项目复盘对话，不走诊断分支边界卡；应读取项目入口清单、项目材料和相关反思聊天记录，并先与用户核对问题池。
